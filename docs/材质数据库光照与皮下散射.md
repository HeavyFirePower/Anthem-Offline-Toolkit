# Anthem 材质数据库、间接光照与皮下散射

目标为本机 Anthem PC 的 Data、Patch 和 Unreal Engine 5.8.4（58902052）。本轮可以按材质查出候选状态及对应字节码，也可以在 D3D11 上执行选中的原始程序，并在 UE 中打开对应材质、改变输入、重做数值对照。

## 手动使用

在包含 `Run-Anthem.ps1` 的目录执行。已有全量索引和原始导出即可使用。`-Output` 可显式指定含 `catalog.sqlite` 和 `raw` 的目录。数据库普查只读原始资产，耗时主要来自大量小 EBX 的磁盘读取。

```powershell
# 数据库、材质引用和每个候选状态的证据
.\Run-Anthem.ps1 -Mode MaterialAudit -Destination output/material-research

# 先运行七个原始 GPU 程序；加 -ImportUE 可建图、重开和比对
.\Run-Anthem.ps1 -Mode MaterialPasses -Destination output/material-research/passes -ImportUE

# 同一张 Strider 厨房桌的三平面饰边材质。使用各自布局内的 owner 和状态编号
.\Run-Anthem.ps1 -Mode MaterialTrace -AssetId 32e32df017609f72b2bbe9ebe8dc7ce92ee7c721d36fa4fac4666b724c8d54bf -StateIndex 10085 -Destination output/material-research/traces
.\Run-Anthem.ps1 -Mode MaterialTrace -AssetId 0f753824e582fe9e9d95b65e3408ea737a670458a260a21e01093fea00d34203 -StateIndex 29205 -Destination output/material-research/traces
```

`libraries.json` 给出每个 RES 的资产 ID、SHA-256、布局、程序池与排列数。`material-families.json` 的每个条目保留变体 EBX 的 ID、记录字节偏移、mesh／material／variation 对象引用、SurfaceShaderId、全局库 ID、首个候选状态及候选数。可先用 `graph_names` 或 `surface_id` 筛选，随后在具体 owner 的 `states.jsonl` 中选择 `index`。导出状态时会得到已映射阶段的 DXBC、反汇编和 VS／PS 常量表。显式选库可传 `-DatabaseId`，局部库要求材质变体与其共享 bundle。参与实际绘制的状态和参数仍需独立的运行时证据。

## 数据库和材质覆盖

| 实际库 | 本机验证范围 |
| --- | --- |
| Data F7，4 库 | gameconfiguration、globals、boot、root。全局库 432,462 条状态 |
| Patch F9，5 库 | gameconfiguration、globals、boot、root、Fort Tarsis 角色创建。全局库 819,356 条状态 |
| 两个系统程序库 | Data 含 79 VS、2,106 PS、1,760 CS。Patch 含 79 VS、2,105 PS、1,744 CS。逐个检查 DXBC 容器和实际阶段 |

九个材质库共 1,298,888 条状态。池内有 23,670 个 VS、56,323 个 PS、76 个 HS、180 个 DS 和 0 个 GS 条目。以上按库计，同一字节码可能重复。工具逐条检查排列引用、状态和常量表边界。F7 与 F9 的常量表起点不同，程序池和解表使用本安装九种内容摘要核对。其他安装若出现新摘要，需要补充布局验证。

7,244 份按布局和内容去重的 MeshVariationDatabase 中读出 300,491 条材质记录，解析错误 0。以“布局、表面 GUID、SurfaceShaderId”为键，Data 的 788 个键有 784 个能在 Data 全局库中找到状态，Patch 的 932 个键有 927 个能在 Patch 全局库中找到状态。对余下的 9 个键检查所有非全局库，并核对变体 EBX 与库的 layout、package、superbundle、bundle。7 个键在本地 root 库命中，Data 3 个、Patch 4 个。合计 1,718/1,720 个键能找到候选状态。余下两键属于采集节点 sapbarnacle 的同一 SurfaceShaderId 1688292972，分别来自 Data 和 Patch。报告的 `local_libraries` 记录局部库 ID、范围、首状态和候选数。图名按本布局中已验证类型的 ShaderGraph 文件 GUID 查找，扫描根目录和嵌套的 `shaders/` 目录，包括 VFX、环境和过场动画资源。1,610 个已匹配表面键能进一步定位具名 ShaderGraph，去重为 655 个图路径。一个图可有多个表面键和大量状态，图名计数、表面键计数和已建 UE 图计数各有自己的分母。

Strider 厨房桌的 `shaders/environments/strider_triplanar_trim` 图，两版都是 SurfaceShaderId 744726293。所查状态分别为 Data 10085 和 Patch 29205。两者的 VS 摘要均以 `c5c26bad` 开头，但 PS 分别为 `b2aea4e4` 和 `c7c5a939`。同一资源名跨版本沿用状态序号或 PS 会得到错误的程序。此前 Spacebear 默认身体的状态 15745 仍对应四输出 PS `080c088b`。[Spacebear 实例、十张纹理与四目标验证](材质实例变体与UE像素对照.md)

两个局部库也做了按 owner 的完整追踪。雨幕圆柱网格 `vfx/meshes/shared/fxm_shr_weather_raincylinder_mesh` 的表面 3874834452 在 Data root 状态 49、Patch root 状态 2897 均提取出实际阶段和参数。复查 Patch 可运行下列命令。

```powershell
.\Run-Anthem.ps1 -Mode MaterialTrace -AssetId cc9e278bcf099ef56b5cf1e1ba81d2665f30f7d7ec045e37afc6b15fad13c355 -DatabaseId e6a1905830d96866967e78e3a7c51c74316beee43f85f71a18eed9b54b47646e -StateIndex 2897 -Destination output/material-research/traces
```

## 在 UE 中打开七个图

在验证工程内容浏览器中打开 `/Game/AnthemValidation/MaterialPasses`。每张图含可编辑参数和 HLSL Custom 节点。光照与扩散的输入是纹理、逐视图常量和逐材质参数，便于在离屏条件下改变单个量并观察输出。

| 原始程序 SHA-256 前缀 | UE 材质 | 已实现并验证的行为 |
| --- | --- | --- |
| `f019b6bf` PS | M_IndirectLight | 从深度和逆视图投影矩阵重建位置，解码六组法线基。读取 FG 表、漫射遮蔽、SSR、tile 材质标志和局部反射列表，生成两个目标。散射使能和强制拆分决定漫射项写入哪个目标 |
| `2631c57b` PS | M_Diffusion | 屏幕空间皮下扩散。GBuffer0.A 量化为表面类别，GBuffer2.R 同时编码 profile 与缩放分量。按开关、投影半径和深度筛选，用各颜色通道的指数系数加权双侧采样。RT0 输出结果，RT1 保留输入 RGBA |
| `83ad0a56` PS | M_DiffuseCombine | 对应像素的 GBuffer1.RGB 乘采样得到的漫射辐照度，输出 alpha 为零 |
| `a0b025c0` PS | M_TileOverlay | 分块内外使用不同混合权重标出边框 |
| `4a9fc3ba` PS | M_OSACoverage | 植被阴影图使用 OSA.B，倍增并饱和，在 0.5 处裁切。选定字节码在 Patch 全局库对应表面 113232320 的 37 个状态 |
| `e01cecfd` PS | M_DissolveAlpha | 对 Dissolve.RGB 用实例向量做点乘，门限约 2/255；随后读取 Alpha.R 并在 0.5 裁切。VFX 图 `vfx/shaders/meshes/fxs_m_diff_rgb_standard_om` 的表面 1369154945 有 61 个候选状态，其中 12 个使用这段字节码 |
| `f80fc9da` VS | M_TileVertexProbe | 从每实例紧凑 tile 记录及顶点角编号计算裁剪空间位置和四分量纹理坐标。原始回放使用 SV_InstanceID、SV_VertexID 和结构化缓冲，UE 探针显式输入同一条记录与编号，并在 VertexInterpolator 的顶点端计算 |

`passes.json` 记录原始字节码的库、偏移、摘要以及三组输入。每组目录存放输入缓冲、原始 GPU 浮点结果和 UE 重开后读回的结果。精度比较使用线性浮点数；图片缩小显示范围以便查看。原始结构化缓冲与 UINT 纹理在 UE 图的输入端分别用可编辑参数或无损整数编码的测试纹理适配。样本使用 64×64 单级纹理和点采样，同一原始输入在不同绑定上可复用。三个参数组是手动构造的测试条件。

## 光照、扩散和逐像素对照

两侧均实测了串联的 GPU 输出。间接光照的 RT1 作为扩散输入，扩散 RT0 再进入漫射合成。其他通道，包括反射和高光，仍可在间接光照 RT0 单独查看。控制组用 8 和 16 像素分块、4 和 8 个采样步、关闭／单 profile／双 profile 开关、强制拆分开关和不同曝光。FPS、时间戳、灯光列表、相机和曝光没有原作历史记录。

| 64×64 输入 | 光照两目标最大绝对误差 | 扩散两目标最大绝对误差 | 串联合成最大绝对误差 |
| --- | ---: | ---: | ---: |
| frame0，散射关闭 | 1.19210×10⁻⁷ | 0 | 0 |
| frame1，开启 profile 1 | 0 | 2.98024×10⁻⁷ | 8.94070×10⁻⁸ |
| frame2，开启 profile 1、2 | 1.19210×10⁻⁷ | 4.17233×10⁻⁷ | 8.94070×10⁻⁸ |

3 组 × 9 个 RGBA 输出 × 4,096 像素，共 110,592 个像素结果。阈值为任一分量绝对误差 0.001，超差像素 0。与关闭扩散相比，两组启用输入分别改变 1,711 和 3,363 个像素超过 0.001。完整精度的 DXBC 采样方向常量很重要，反汇编文本会把立即数显示到六位小数，直接抄录会在点采样边界选中邻近纹素。VS 的 540 个原始流输出顶点通过解码公式核对，UE 顶点端另取 36 个样本，每个 8 个分量，最大误差 0。

`passes-comparison.png` 的七列依次为间接光照、扩散、漫射合成、tile 边界、OSA、溶解及串联合成。每组三行依次显示原始 DXBC、UE 和 RGB 绝对差的放大图。统计包含双目标和 alpha；PNG 展示各程序第一个目标的 RGB。两个遮罩图连接到 UE 的 Opacity Mask，离屏像素对照使用零背景。浮点输出与完整指标见同目录的 `passes-comparison.json`。

## 原作画面与当前边界

取得四张玩家历史录像截图后，已定位大厅地板、重建三槽表面，并验证浮雕和砖地两组候选延迟程序，并对两张录像的浮雕局部画面进行验收。双视角使用同一组光源，保留单视角预测远景的独立结果。采集节点缺失键也已跨全部九个材质库再次核查。命令、误差和图例见[录像画面与地板材质](录像画面与地板材质.md)。

Fort Tarsis 的安装包内有可追溯的视觉参考。`configurations/ui/loadingscreensources/loadscreens_tarsis` 的 EBX 字符串指定 `UI/Loading/Textures/LoadScreen_FortTarsis`。其实际纹理为 728×868、BC1、单 mip，可看到逆光下的塔、围墙以及前景植被。可复现导出如下。

```powershell
.\Run-Anthem.ps1 -Mode Texture -Match ui/loading/textures/loadscreen_forttarsis -Destination output/material-research/scene-reference
.\vendor\DirectXTex\texconv.exe -nologo -y -ft png -o output/material-research/scene-reference output/material-research/scene-reference/7e60804f6166e5c2/594b0159b36007ce/source.dds
```

这张图能参考构图、明暗和色彩。它属于加载画面，缺少对应的相机矩阵、曝光、天气、逐 draw 状态、历史缓冲和 GBuffer。公开的早期 Fort Tarsis 实机演示也可供人工观察。在这些素材上计算的差值不能用于认证本安装、同一镜头的材质误差。[BioWare 演示的 Fort Tarsis 早期实机画面](https://www.youtube.com/watch?v=u2uJPeuUeMQ)

本轮覆盖一组间接光照与屏幕空间扩散程序。其余直接光／阴影、透射／厚度、不同扩散核、时域历史、雾、曝光和色调映射需要逐程序验证。UE 的 Subsurface Profile 可用于制作另一种表面外观，但其内置参数与本程序的八项 profile、深度权重和分块状态没有建立逐项等价关系。要扩展目前结果，应保留原始字节码和同输入的浮点读回。[Epic Subsurface Profile](https://dev.epicgames.com/documentation/unreal-engine/subsurface-profile-shading-model-in-unreal-engine)
