# Anthem 离线解包操作教程

已有全量解包时，可以直接使用 `StaticMesh` 和 `StaticScene`。具体选项和本机样本见[静态模型与场景](静态模型与场景.md)。

目标环境是 Windows x64、Python 3.12、Unreal Engine 5.8.4。已在本机确认引擎构建号 58902052。输入游戏构建信息为 2020-02-18、Frostbite 2017.7；不同版本的文件应使用新的输出目录。

## 目录和依赖

| 路径 | 用途 |
| --- | --- |
| `Games/Anthem` | 原始游戏文件，只读；需要 Data、Patch 和游戏自带的 `oo2core_7_win64.dll` |
| `vendor/anthemtool` | 开源解析器，附带本项目的格式修复和 MIT 许可 |
| `vendor/DirectXTex/texconv.exe` | 微软纹理解码工具，只用于派生导入文件 |
| `tools` | 索引、解压、格式转换和验证脚本 |
| `output/anthem` | 完整提取任务的目录，目前索引未完成 |
| `output/sample` | 本次小样本及验证结果 |
| `ue/AnthemValidation` | UE 导入验证项目；不是还原完成的游戏关卡 |

核心 Python 工具只使用标准库，不需要运行上游 `setup.py`，也不需要 diskcache。不要把从其他地方取得的 Oodle DLL 覆盖进游戏目录。

## 工具放置位置和游戏路径

支持两种布局，均可直接运行 `.\Run-Anthem.ps1 -Mode Index`：

| 工具所在位置 | 自动识别的游戏目录 | 默认输出 |
| --- | --- | --- |
| 本项目根目录，下面有 `Games/Anthem` | 工具目录下的 `Games/Anthem` | 工具目录下的 `output/anthem` |
| 游戏目录，旁边直接有 `Data`、`Patch` | 工具目录自身 | 游戏目录旁的 `Anthem-Extracted/anthem` |

后一种布局的样本放在 `Anthem-Extracted/sample`。本文后续的 `output/sample` 和 `output/anthem` 示例均以第一种布局为基准；直接在游戏目录运行时，请使用旁边的实际输出路径。

只检查路径，不创建输出、不启动索引：

```powershell
.\Run-Anthem.ps1 -CheckPaths
```

也可显式指定游戏和输出。游戏目录必须直接包含 `Data/layout.toc` 和 `Patch/layout.toc`：

```powershell
.\Run-Anthem.ps1 -Mode Index -GameRoot 'E:\TitanExclusion\Tools\Anthem\Games\Anthem' -Output 'E:\TitanExclusion\Tools\Anthem\Games\Anthem-Extracted\anthem'
```

相对路径参数相对于脚本所在目录解析。Python 入口可使用 `--game` 和 `--out`；其相对路径相对于执行命令时的当前目录解析。工具会在创建索引前验证输入目录。输出不能放在游戏目录内，以免生成文件干扰输入校验；工具自身的已知目录和文档也不会计入游戏指纹。

## 查看本次样本

```powershell
Set-Location E:\TitanExclusion\Tools\Anthem
.\Run-Anthem.ps1 -Mode Report -Output output/sample
python tools/anthem_pipeline.py query --out output/sample --match MeshSet
python tools/anthem_pipeline.py query --out output/sample --match Shader
```

原始导出路径使用哈希命名以避免 Windows 路径长度、重名与不同补丁版本相互覆盖。原始资产名称在 `catalog.sqlite` 的 `asset.name` 中；`asset.output` 是相对输出目录的文件路径。SQLite 工具或 Python 都可以查询。不能仅凭目录中的哈希文件名判断资源用途。

常用结果：

- `summary.json`：每类原始资源数量、状态、字节数。
- `catalog.sqlite`：资源 GUID、RES RID、16 字节 meta、CAS 位置、输出 SHA-256 与所有已索引 bundle 引用。
- `textures/manifest.json`：纹理格式、尺寸、mip 尺寸、原始 chunk、DDS 和导入纹理路径。
- `meshes/manifest.json`：MeshSet 类型、LOD、顶点声明、几何 chunk、OBJ 转换状态。
- `shaders/manifest.jsonl`：Shader 对应的资源和数据库内偏移；`reflection_report.json`：常量与资源绑定。
- `ue_import_report.json`：实际执行的引擎版本与逐个导入结果。

## 手动全量索引和解包

```powershell
.\Run-Anthem.ps1 -Mode Index
.\Run-Anthem.ps1 -Mode Extract
```

Index 会解析 Data 和 Patch，保留历史版本和 bundle 成员关系。原始安装约 86.1 GB；由于保留历史版本、重复位置和解压数据，输出空间可能显著超过安装大小。索引阶段不导出整套资源，耗时取决于磁盘和 SQLite 写入速度。

Extract 默认不限数量。断开后再次执行相同命令，会校验已完成文件的大小和 SHA-256，然后跳过它们；校验失败会重新提取。写入先经过 `.part` 临时文件，只有块长度与资源长度校验通过才替换目标。`error` 记录不会被当作成功。

若更新了游戏文件，使用新输出目录保留旧证据：

```powershell
.\Run-Anthem.ps1 -Mode Index -Output output/another_build
.\Run-Anthem.ps1 -Mode Extract -Output output/another_build
```

缺失语言包会显示 unavailable。不要把所有 unavailable 都视为“可忽略语言”：例如 conversationperformances、默认 bundle、调试安装包也可能列出；查看 `pipeline.log` 和实际安装内容确定范围。

## 按类型或名字选取

```powershell
python tools/anthem_pipeline.py query --match Texture --limit 20
python tools/anthem_pipeline.py extract --kind Resource --match MeshSet --limit 20
python tools/anthem_pipeline.py extract --kind Ebx --match shader --limit 20
```

`--limit` 限制本次选择的记录总数，包括已存在的记录，不表示“新增多少个”。按名字提取不会自动导出所有依赖；纹理头不是像素数据，MeshSet 头也不是完整顶点数据。

从现有索引重建默认样本并补充其纹理和网格 chunk：

```powershell
.\Run-Anthem.ps1 -Mode Sample
```

Sample 输出到该布局的默认样本目录（项目布局为 `output/sample`，游戏目录布局为旁边的 `Anthem-Extracted/sample`），不会清空已有样本。它可以使用明确标记为未完成的源索引做局部测试，但不能据此声称覆盖全游戏。`resolve_texture_chunks.py` 会重新读取所有安装包的元数据，仅提取已选纹理和网格的相关 GUID。

## 转换样本

```powershell
.\Run-Anthem.ps1 -Mode Convert -Output output/sample -Limit 64
```

执行顺序为 DDS 重建、TGA 解码、刚性网格 OBJ、Shader 提取和静态反射报告。返回状态有 unsupported 时，阅读对应 manifest；转换脚本保留原始文件，不能因为脚本进程结束就将所有条目视为转换成功。

基础 Convert 的 TGA 预览只含普通二维纹理的顶层 mip。使用 `Texture` 或 `TextureSamples` 可导出保留原始格式、sRGB 标记和完整 mip 的 DDS，以及适合 UE 导入的解码副本。HDR、深度、Cube、数组和 3D 各有实际样本。查询材质槽、查看 RGBA 并复现 UE 回读的方法见[纹理教程](纹理格式与RGBA通道.md)。

网格：OBJ 是源坐标下的位置、法线和 UV0 几何预览，保留 section 分组。不会自动假定米到厘米、翻转坐标轴或应用骨架。原始切线、颜色、其他 UV 和骨骼属性仍在原始 chunk 中；高保真材质验证应使用后续保留全部顶点属性的转换器。

Shader：`.dxbc` 保存编译后的程序，`.asm` 保存微软 D3DDisassemble 输出。反汇编不等于原始 HLSL，也不能直接当作 UE Custom 节点源码。

单独执行各步骤：

```powershell
python tools/texture_export.py --out output/sample
python tools/prepare_ue_textures.py --out output/sample
python tools/mesh_export.py --out output/sample
python tools/shader_extract.py --out output/sample --limit 64
python tools/shader_report.py --out output/sample
```

`shader_extract --limit 0` 扫描导出的全部 RES；相同字节码按 SHA-256 去重，manifest 仍记录来源。它只识别结构有效且存在可执行 Shader chunk 的 DXBC 容器，不保证专有压缩、拆分或其他布局的程序都能识别。

## UE 5.8.4 验证

```powershell
.\tools\Validate-UE.ps1
```

脚本检查精确引擎版本，并把已成功转换的 TGA/OBJ 导入专用 `/Game/AnthemValidation` 目录。重复验证会替换该目录下同名的测试资产；不要在那里手工保存生产修改。需要正常可写的 UE 缓存环境和显卡驱动。

本机实测：UE 的 DDS Interchange 导入器拒绝样本的 BC1、BC3、BC5 压缩 DDS，因此先用随附 DirectXTex 解码为 TGA。DDS 继续作为原始纹理归档。

UE 验证包含类型检查和非零网格几何检查，不包含原作画面对比、材质图正确性或骨骼动画验收。

## 常见问题

“Index not complete”：先完成 Index。不要手动把数据库的完成标记改为 true。索引中断后重跑会重新读取元数据并补齐去重记录。

“Input fingerprint changed”：游戏路径、文件大小/时间或 TOC/SB 哈希发生变化；新建输出目录，不混用不同安装版本。

“No exported full mip-chain chunk”：运行样本依赖补齐，或在完整导出中确保 TocResource 和 Chunk 都已完成。仅有低 mip 数据时禁止伪装成原始分辨率。

“Multiple payload variants”：同 GUID 存在不同内容；需要用具体 bundle/补丁上下文判断。不要简单按文件修改时间取最新。

“Unsupported”：属于格式覆盖范围不足，原始资源仍可继续研究；不要改扩展名冒充 FBX、WAV 或材质文件。
