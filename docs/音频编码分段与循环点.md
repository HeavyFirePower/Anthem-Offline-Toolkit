# Anthem 音频编码、分段 WAV 与循环点

## 手动提取一条声音

在游戏目录打开 PowerShell。已有全量解包时，直接使用旁边的 `Anthem-Extracted/anthem`。如果解包目录在别处，在命令中加 `-Output '含 catalog.sqlite 和 raw 的目录'`。输出路径可自选。

```powershell
$dst = Join-Path $PWD 'output/audio-study'
$name = 'sound/sfx/soundwaves/gameplay/gear/ranger/offensivelauncher/laser/abi_exm_projectilelauncher_laser_beam_noise_ext_lp'
.\Run-Anthem.ps1 -Mode Audio -Match $name -Variation 0 -Destination $dst
```

命令打印 `audio.json` 的绝对路径。旁边的 `audio.wav` 是完整的有符号 16 位 PCM，可在音频编辑器中打开。JSON 记录原库与 chunk 的 ID、GUID、SHA-256、每个 SPS 的原始偏移、字节长度与编码、各段在 WAV 的起始帧、帧数、采样率及每段 PCM 哈希。WAV 包含一次完整播放的起音、循环体和收尾。

不知道完整路径时可以先查目录。例如查找酒吧内播放的音乐：

```powershell
.\Run-Anthem.ps1 -Mode AudioList -Match 'mus_diegetic_bar' -Destination $dst
Get-Content "$dst/audio-list.json" -Raw | ConvertFrom-Json | Format-Table name,id,variations
```

`AudioList -Match` 为路径子串查询。`Audio -Match` 为完整逻辑名查询，同名的不同库内容分别输出。要精确重现本安装的一份音乐库，可用下面的目录 ID。变体编号从 0 开始，本例只提取第 4 号变体。

```powershell
.\Run-Anthem.ps1 -Mode Audio -AssetId 2e8a467f12ee84351e15942ff179c4aee5a6821f7177d158e1f25448fdefa21b -Variation 4 -Destination $dst
```

`-All` 导出指定库的每个变体，各写一个 WAV。`-ImportUE` 可加在 `Audio` 或 `AudioSamples` 上，使用验证项目的 `/Game/AnthemValidation/Audio` 目录。离线 WAV 导出随工具包提供 Windows x64 版 vgmstream r2168 及所需 DLL。[vgmstream 发布包](https://github.com/vgmstream/vgmstream/releases/tag/r2168)

## 本安装的实际支持范围

32,836 条 NewWaveResource 记录含 4,350 个不同逻辑名、4,411 份不同内容的库。按库内容去重后，共 24,265 个变体，187 个由多段组成。全部 25,257 次分段引用都定位到了完整的 SPS 块链，对应 24,875 个独立的「源 chunk 内容＋起始偏移」位置。以采样率换算，库表浮点时长与 SPS 整数帧数的差异全都小于一帧，最大 0.65625 帧。

| 实际编码 | SPS 编码 ID | 分段引用次数 | 实测声道与采样率 |
| --- | --- | ---: | --- |
| EA XAS v1 ADPCM | 4 | 24,727 | 44.1 kHz 双声道；48 kHz 的 1、2、4、6、8 声道；96 kHz 的 1、2、4 声道；192 kHz 双声道 |
| EALayer3 v2 PCM | 6 | 529 | 44.1 kHz 双声道；48 kHz 的 1、2、6 声道。这里的 PCM 是 EA 编码变体名，导出仍经过 EALayer3 解码。 |
| EA Opus | 12 | 1 | 48 kHz 单声道；样本为 `abi_exm_lancer_grenade_pin_hud` |

18 个代表变体共 31 段，覆盖全部 15 种实际的「编码、声道数、采样率」组合，含内存块、流式块和带起音／收尾的循环。18/18 已生成 WAV，并在 UE 5.8.4 保存、重开后逐个验证声道、采样率、时长、完整源 PCM 哈希及原生循环范围。多声道 WAV 保留解码器输出的通道次序；各关卡对声道的扬声器分配和空间定位仍需运行时路由信息。

143 个变体有可明确解释的库表循环范围。另有 24,122 个变体的循环段为 `0,0`，且无独立 SPS 循环标志，其中 24,078 个只有一段，44 个有多段。对应 WAV 保留一次完整播放。原始库和 SPS 中未确定的游戏播放开关，记录在 JSON 中供后续追查。

## 怎样找到正确的音频段

NewWaveResource 是小端 Harmony 库。工具从 `Chunks` 读取 GUID、完整 chunk 长度，从 `Variations` 读取变体 ID、首段索引、段数、内存／流送块索引，再按 `Segments` 的表序读取。采样数据地址采用 `SamplesOffset & ~3`。本安装里低两位为 1 的段取 MemoryChunkIndex，为 3 的段取 StreamChunkIndex。一个变体可以同时声明两类 chunk；实测有仅几十字节的内存块保存查找数据，音频头和有效负载在流送块中。工具按 GUID 和完整长度查找 Chunk／TocResource，出现不同内容候选时保留错误及来源，不按文件名选补丁。[Harmony 表结构](https://github.com/NicknineTheEagle/Frostbite-Scripts/blob/a07ee6d38ecc62598dfc9fdf990be067d9f21929/frostbite3/sbr.py)

EA AudioCore 的 SPS 头使用大端字段。工具读取四位编码编号、声道数、18 位采样率及 29 位音频帧数，再沿 H、D、E 块头给出的长度走到结束块。实测部分 E 块包含对齐填充，不能按固定四字节切段。每段单独交给解码器，一次解码后按原始顺序拼接交错 PCM；各变体保持独立。导出时比较解码器报告、原始 SPS 声道／采样率／帧数与每段 WAV，并再打开最终 WAV，逐段核对 PCM 和边界。[EA AudioCore 解码器](https://github.com/vgmstream/vgmstream/blob/r2168/src/meta/ea_eaac.c)

## 怎样使用循环点

音频位置以**每声道的采样帧**计数。一帧同时包含同一时刻的所有声道。JSON 的区间记为 `[start, end_exclusive)`。RIFF 的 `smpl` 使用包含末帧的端点，写入 WAV 时将结束值减 1。只写有来源的前向循环，不在文件中重复循环体或添加淡出。[RIFF/WAVE 采样器循环规范](https://www.mmsp.ece.mcgill.ca/Documents/AudioFormats/WAVE/Docs/RIFFNEW.pdf)

| 循环信息来源 | 工具行为 |
| --- | --- |
| 变体给出可区分的 FirstLoopSegmentIndex 和 LastLoopSegmentIndex 范围 | 索引相对变体首段，两端包含。起点为之前各段帧数之和，终点为截至最后循环段的累计帧数。例 `1,1` 表示只有第 1 段循环。 |
| SPS 本身设置 loop flag | 读取 SPS 的起始帧，以该段帧数为终点，加上这段在拼接 WAV 中的起点。报告标记来源。 |
| 区间为默认 `0,0` 且无独立 SPS 循环标志 | 保留原值，标记 `undetermined_0_0`，不写 `smpl`。这包括一段声音以及某些多段声音。文件名中的 `_lp` 不能证明游戏循环的是整段还是其中一部分。 |
| 多个明确来源给出不同区间 | 报告列出 `conflicting_ranges` 和候选；输出单遍 PCM，留待播放图确认。 |

上面的激光音效由 **38,400 + 192,000 + 38,400** 帧组成，为 96 kHz 立体声。起音 0.4 秒，循环体 2 秒，收尾 0.4 秒。整个 WAV 为 268,800 帧。JSON 循环区间是 **[38,400, 230,400)**；用支持 WAV 循环标记的编辑器查看，`smpl` 的末帧为 **230,399**。

UE 5.8.4 的默认导入器在这个文件上返回了起始帧 38,400、长度 191,999。工具保留标准 WAV，通过随包的编辑器插件按源区间设置 SoundWave 的原生循环长度，并重新打开已保存的资产核对。检查 `ue-audio-readback.json` 中的 `ue_native_loop_regions` 和 `pcm_exact`。循环区间描述可重复的范围，实际进入循环、退出循环以及转入哪个音乐状态，仍由播放逻辑决定。

## 普查和样本复验

```powershell
$dst = Join-Path $PWD 'output/audio-study'
.\Run-Anthem.ps1 -Mode AudioAudit -Destination $dst
.\Run-Anthem.ps1 -Mode AudioSamples -Destination $dst -ImportUE
```

`audio-audit.json` 按库内容 SHA-256 去重，统计可解析变体、段引用数、独立 SPS 地址、编码与声道／采样率组合，列出未解析条目。普查检查库头、目录候选、文件大小、SPS 头和块边界。单个文件导出时另做完整 chunk 哈希及实际解码。`AudioSamples` 按实有格式组合和循环结构取样，优先选择时长适中的小样本。它会在需要时生成普查报告，运行结果写入 `samples.json`。

语音库样本 `vo_ep_dominion_trooper_m4_jump_land_heavy` 的第 0 号变体为 48 kHz 单声道，共 24,084 帧。酒吧音乐样本 `mus_diegetic_bar` 的第 4 号变体为 48 kHz 立体声，共 2,652,744 帧。全量 NewWave 与英文对话已经完成逐条 PCM 验收，默认循环开关需按采样器引用查询。音乐事件、语言和总线可分别追到实际 EBX。[逐条解码、播放图与语音绑定](音频播放图与语音绑定.md)
