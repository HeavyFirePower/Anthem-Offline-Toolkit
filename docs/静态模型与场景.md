# Anthem 静态模型导出与 UE 5.8.4 导入

需要浏览目录、抽样或把各级 LOD 保存为同一个 UE 资产时，可使用[静态模型图形工具](静态模型图形工具.md)。两个 Python 窗口分别负责导出和导入。

已有全量解包时，直接使用包含 `catalog.sqlite` 和 `raw` 的目录。本机是 `E:\TitanExclusion\Tools\Anthem\Games\Anthem-Extracted\anthem`。下面的命令在工具目录或已安装工具的游戏目录中运行。入口打开只读索引。

## 导出第一个 FBX

```powershell
.\Run-Anthem.ps1 -Mode StaticMesh -Match gbl_prp_junktriangle_mesh -Limit 1
```

这是一个含五套常规 UV 的道具。输出在全量解包目录下的 `static\<资产 ID>\render_fbx_lod0`。资源原名保留在文件名和 `manifest.json` 中。默认取 LOD0 的不透明、透明和贴花渲染子集。阴影和深度预通过可能重用同一表面，导出研究用全子集时加 `-AllPasses`。

```powershell
# 指定全量解包目录和目标目录，按完整 ID 选定一个版本
$catalog = 'E:\TitanExclusion\Tools\Anthem\Games\Anthem-Extracted\anthem'
$dest = 'E:\TitanExclusion\Tools\Anthem\output\my-static'
.\Run-Anthem.ps1 -Mode StaticMesh -Output $catalog -Destination $dest -AssetId 576464a592a1aeafb819543b5c1931d8c700fee2db46f7520e0faca56ef8ddef -AllLods -Format both

# 解析原始碰撞并连同渲染网格导出
.\Run-Anthem.ps1 -Mode StaticMesh -Output $catalog -Destination $dest -Match ant_res_bunkbed02_mesh -Limit 1 -Collision

# 单选 LOD、导出独立 USD 网格
.\Run-Anthem.ps1 -Mode StaticMesh -Output $catalog -Destination $dest -Match prt_str_set_roof_40m_01_mesh -Lod 2 -Format usd

# 手动批量转换刚性与复合资源，先用 Match 和 Limit 估算容量
.\Run-Anthem.ps1 -Mode StaticMesh -Output $catalog -Destination $dest -All -AllLods
```

FBX 导出使用工具包内的 Windows x64 写入器和本机 UE 自带的 Autodesk FBX SDK 2020.2。默认读取 `C:\Program Files\Epic Games\UE_5.8\Engine\Binaries\ThirdParty\FBX\2020.2\Win64\libfbxsdk.dll`。自定义安装目录时，把 `$env:ANTHEM_FBX_SDK_BIN` 设为包含该 DLL 的目录。USD 写入只需要 Python。每个 LOD 独立成文件，可以在 UE 静态网格编辑器中逐级导入。原有 OBJ 几何预览仍由 `tools/mesh_export.py` 提供。

## 哪些数据进入文件

| 游戏数据 | FBX / USD 对应关系 |
|---|---|
| Position、索引 | 保留源顶点和三角面顺序。使用 Y 向上、米。处理内联数据、外部 Chunk、16 位与 32 位索引。TrianglePatch 输出控制三角形，离线几何不包含运行时位移细分。 |
| Normal、Tangent、Binormal、BinormalSign | 法线取源向量 XYZ。显式切线按 Frosty 的转换约定取负。存在独立副切线时读取源值，仅有符号时用 `cross(N,T) * sign` 得到副切线。缺失的通道在清单里标为缺失。 |
| Color0、Color1 | RGBA 各四分量写为独立 FBX 顶点色层。USD 同时保存命名 primvar。UE 常规 Static Mesh 顶点色工作流使用一套 RGBA，依赖 Color1 的材质需要单独映射该数据。 |
| UV0–UV4 | 按源通道排序，FBX 写为 UV0、UV1 等，USD 写为 st、st1 等。交换文件记录 `(U,1−V)`。RadiosityUV、DisplacementUV 使用独立名称排在常规 UV 后。 |
| 材质 | 保留 section 名、材质槽名与源材质 ID。FBX 槽指向占位材质。重建 Shader 时可用这份清单关联参数和贴图。 |
| 完整顶点声明 | 每个 LOD 的 `.attributes.json.gz` 含逐 section 的声明、stream 和各顶点的原始语义分量。保存 Position.w、Normal.w、Tangent.w、原始 UV、辐射度 UV 的第三分量、位移 UV 的四分量以及子材质索引等；UByte4N 在此文件中记录为 byte/255。原始字节仍在 raw 中。 |

`-AllPasses` 可用于检查仅含位置的阴影子集。个别刚性资源保留了骨骼权重字段，伴随文件保存这些字段，渲染网格取静态姿态。未识别的声明、越界索引、关联不唯一的 Chunk 会在清单中给出原因。

## UE 5.8.4 导入

1. 在 Content Browser 导入 LOD0 FBX。来源单位选米或启用 Convert Scene Unit。导入法线与切线选择 Import Normals and Tangents，顶点色选择 Replace。
2. 核对原始 UV 时关闭 Generate Lightmap UVs。打开 Static Mesh Editor 的 UV 列表，将通道数量与清单比较。合并导入多个渲染 section 时，材质槽名称可用来识别源 section。
3. 对 `-Collision` 的 FBX，关闭 Generate Missing Collision，启用 One Convex Hull Per UCX。清单的 `fbx_render_nodes` 等于 1 时关闭 Combine Meshes。选择 Show Simple Collision 检查原始凸包。自动生成的碰撞会干扰计数验证。
4. 各 LOD 文件用于同一个 Static Mesh 时，在 LOD 设置里逐级导入。若 UE 构建设置启用了 Recompute Normals 或 Recompute Tangents，关闭这两项后再核对源切线。

上述 UE 验证使用 FBX Factory。Interchange、DCC 软件和其他引擎对多套顶点色以及辅助 UV 的消费方式可能不同。源值可以在伴随文件中复查。[Epic FBX 导入选项](https://dev.epicgames.com/documentation/en-us/unreal-engine/fbx-import-options-reference-in-unreal-engine)

## 原始碰撞的关联

`-Collision` 通过同一对象 EBX 的两组导入引用确认渲染资源与 PhysicsAsset，再通过两端的 Resource ID 选中 MeshSet 和 PhysicsResource。候选文件名用于缩小查找范围。版本不唯一、缺少关联或物理布局不支持时，清单写明原因，已解出的渲染几何仍可使用。

Anthem v2 的球形从半径建立，胶囊从轴段两端点和半径建立。箱体必须能从源顶点得到八个长方体角点，并通过凸体边界检查。一般凸体从源顶点和支撑平面恢复面，再对照原始边表。所有部件都应用源旋转和平移。FBX 分别写成 USP、UCP、UBX、UCX 节点，USD 网格保留渲染几何。遗迹门的 UE BodySetup 回读到两个箱体、两个胶囊，工业管道回读到两个胶囊。四个胶囊的半径和轴段长度与源值之差都小于 0.001 厘米。[Epic 的 FBX 碰撞命名与导入规则](https://dev.epicgames.com/documentation/unreal-engine/fbx-static-mesh-pipeline-in-unreal-engine)

物理资源全量扫描按内容去重，共 5,297 份。2,346 份的全部形状通过解码（44.29%），合计 3,963 个箱体、1,334 个胶囊、162 个球和 1,927 个凸包。其余 2,951 份保留失败原因，其中 168 份另有局部三角形可导出。这个分母涵盖关卡和动态物体。网格绑定需要对应所有者的引用，刚体行为另行验收。

## 关卡静态实例

```powershell
.\Run-Anthem.ps1 -Mode StaticScene -Output $catalog -Destination $dest -AssetId 5764290c7bfd0319d24e7fcbbadf481186d76cb5acc9cff4662289a9ce06abfa
```

也可以给 `-Match` 传入关卡 EBX 的完整资源名。同名多个不同内容版本需用 `-AssetId` 选择。首次解析可能要扫描大型目录并读取跨 bundle 的 EBX 头部。

打开输出的 `scene.usda` 并保留同目录的 `mesh_*.usda`。从蓝图根对象或 Objects 数组出发，转换器读取 StaticModelGroupEntityData、StaticModelEntityData 和 DebrisClusterData 的静态姿态，通过 MeshAsset 的文件 GUID、对象 GUID 和 MeshSet RID 找到几何。ObjectReferenceObjectData 和 SpatialPrefabReferenceObjectData 可在根场景所属 bundle 的并集内逐层展开。每层按子矩阵乘以父矩阵组合，源引用路径、材质变体指针和七个渲染覆盖字段保存在清单里。非零渲染覆盖也写入 USD 自定义属性。空覆盖数组可继续解析，有内容的模板或逐实例对象覆盖保留原因。

在 Antium 的四米栈道与吧台样本中，OpenUSD 分别读回 3 个实例／2 个原型、9 个实例／4 个原型。另有双层床蓝图和陶罐碎片蓝图各 1 个实例。14 个实例的矩阵逐分量回读一致。MeshProxyEntityData 可追踪到目标类型，Storm 头盔实际引用 SkinnedMeshAsset，场景清单将它列入未转换并指向骨骼流程。`other_root_types` 汇总所选蓝图中场景导出器未处理的根对象类型，`total` 只统计进入放置解析的记录。

## 复合 MeshSet 的静态姿态

140 份复合 MeshSet 均使用 UShort4 顶点部件索引。读取每个 section 的 192 位部件掩码，校验顶点索引属于该掩码、每个三角面的三个顶点属于同一部件，再把位置和切线基变换到模型空间。45 份资源带独立部件变换表，另外 95 份使用原始模型空间。FBX 按材质 section 输出可导入的静态网格。USD 额外保留逐顶点的 `primvars:anthem:partId`，伴随文件保存原始顶点分量，清单保存部件矩阵和源包围盒。

陶罐有 8 个部件和显式平移。OpenUSD 将每个导出点与原始局部位置乘以对应矩阵后的结果逐点比较。另一份五部件木托盘带 3 个 LOD，可用于检查省略矩阵表时的单位变换。以上输出保留固定姿态，碎裂、部件约束和激活顺序仍属于运行时物理。

```powershell
# 带部件变换的陶罐，同时保留 FBX 和 USD
.\Run-Anthem.ps1 -Mode StaticMesh -AssetId 11016100fff44ed11a1e6cf28bf6102f5e2cd5d555530468b432a9f5d22a53bc -Format both
# 遗迹门的箱体和胶囊
.\Run-Anthem.ps1 -Mode StaticMesh -AssetId bd12fde7d18ae2b32aa7834f98464ea2687fa4ddceb874d4c7ac51e0e5eb4869 -Collision
# 栈道预制体的三个实例
.\Run-Anthem.ps1 -Mode StaticScene -AssetId 41da8748aab198d2b2083173e420ab4a80e9adbeb7c1ce290be4532eddf1493b
```

## 逐资产覆盖报告

下面的命令使用现有解包目录。StaticAudit 逐份生成临时二进制 FBX，用 Autodesk SDK 重新打开，核对节点、控制点、三角索引及各层的数组长度，然后删除临时 FBX。StaticPhysicsAudit 独立解码每份 PhysicsResource。碰撞与某个渲染模型的关联还需要通过 `-Collision` 核对双方所有者。

```powershell
.\Run-Anthem.ps1 -Mode StaticAudit -Output $catalog -Destination $dest
.\Run-Anthem.ps1 -Mode StaticAudit -Output $catalog -Destination $dest -AllLods
.\Run-Anthem.ps1 -Mode StaticPhysicsAudit -Output $catalog -Destination $dest

# 查某个资产在每一级 LOD 的结果
Get-Content "$dest\asset-coverage-all-lods.jsonl" | ForEach-Object { $_ | ConvertFrom-Json } |
    Where-Object name -Like '*woodpallet02_mesh' | Select-Object -ExpandProperty lod_results
```

每条 MeshSet 明细按源文件 SHA-256 与 RES 元数据去重，记录代表 ID、资源名和重复条目数。1,233 份骨骼资源单列为 excluded。LOD0 的 5,097 份刚性和 140 份复合全部完成，涉及 7,986 个渲染 section、15,102,187 个三角面和 53,224 个 SDK 数组。全目录统计核对数组长度，保留的 FBX 样本另对数组内容做哈希比对。阴影、深度专用 section 需要手动启用 `-AllPasses`，未计入上述渲染覆盖率。

`-AllLods` 实际写入并回读全部 17,512 个 LOD（刚性 17,095 个、复合 417 个），涵盖 28,090 个渲染 section、28,611,302 个三角面和 188,920 个数组。逐资产的 `lod_results` 列出每级的三角面数、顶点数、数组数和临时 FBX 的 SHA-256。前一轮对 7 个留存 FBX 的 73 个数组做过逐值哈希核对。本轮全目录 LOD0 的 UE 结果见下节。

环饰 `prt_str_ringdecoration_01_mesh` 的 FBX 保留全部 910 个面，UE 5.8.4 构建后有 786 个面。源数据中正好有 124 个零面积面。清单中的 `zero_area_triangles` 可用于区分这类数量差异。工作区 `output/static-study` 保存逐资产和逐物理资源的 JSONL，`samples` 保存本轮样本、SDK、OpenUSD 及 UE 回读报告。

## 全目录 UE 导入与阴影、深度子集

在当前安装的游戏目录运行以下命令即可使用已有解包。默认写到解包目录的 `static-audit`。全量验证的 5,237 个 FBX 约占 0.7 GB，导入使用 UE 5.8.4 的 FBX 工厂与临时资产，磁盘保留 FBX 和逐资产报告。需要把模型长期放入自己的工程时，可从选定的 FBX 正常导入。

```powershell
# 只核对源 section，不启动 UE
.\Run-Anthem.ps1 -Mode StaticPassAudit
# 生成全目录普通 LOD0 FBX，在本机 UE 中逐份导入和回读
.\Run-Anthem.ps1 -Mode StaticPassAudit -ImportUE -Workers 8
```

按 MeshSet 内容与 RES 元数据去重，普通 LOD0 共 5,237 份，UE 成功创建 5,235 份。4,834 份的构建三角数和 UV 通道数与源一致。另 401 份的 UV 数一致，三角数差恰等于源零面积面数。`env_obj_des_collision_square_4m_mesh` 和 `env_obj_des_collision_square_8m_mesh` 各有一个源面，源浮点坐标计算的面积非零，FBX 工厂把它们判为全退化并拒绝建网格。逐项结果在 `ue-lod0.jsonl`，汇总在 `ue-summary.json`。重新运行导入时只复用 UE 版本、源期望值及实际 FBX 字节哈希均匹配的结果。

| 源子集，所有 LOD | 含该子集的静态资产 | 完成几何解码的非空 section | 三角面 |
| --- | ---: | ---: | ---: |
| 深度（ZOnly，类别 3） | 4,905 | 19,549 / 19,549 | 27,914,324 |
| 阴影（Shadow，类别 4） | 4,923 | 9,479 / 9,479 | 8,000,389 |
| 只用于深度或阴影，剔除属于常规类别 0–2 的 section，并集合并 | 4,536 | 20,082 / 20,082 | 27,935,034 |

同一个 section 可以同时用于多个 pass。逐资产明细 `passes.jsonl` 记录源类别、LOD、section 序号、三角面数与解码状态。可用 `-MeshPass depth`、`shadow` 或 `dedicated` 只导出相应几何，用 `-AllLods` 遍历各级。两者皆有的 section 在 `dedicated` 文件中只出现一次。墙板样本的深度文件含 section 2、3，阴影文件含 4、5，各 58 个面。三个 FBX 的 20 组 SDK 数组逐值比对通过，三个 USD 均已回读。UE 分别构建出 58 面的深度网格、58 面的阴影网格和 116 面的并集，各有 1 个 UV 通道。原作选择哪个 LOD、投射哪盏灯的阴影以及最终屏幕深度仍需渲染证据。

```powershell
$wall = '479d25b18089836fec075ede7fed8ade125e1e4366fd8a9d12ef147b9980ed94'
.\Run-Anthem.ps1 -Mode StaticMesh -AssetId $wall -MeshPass shadow -Format both
.\Run-Anthem.ps1 -Mode StaticMesh -AssetId $wall -MeshPass depth -Format both
```

## 带树碰撞、多刚体与碎裂部件

5,297 份物理资源里有 1,990 份带树。单叶球形样本通过源半径、中心与独立包围盒检查。另有 168 份资源能还原三顶点形状的局部坐标、源索引和部件引用，共 121,489 处引用。选中冰罐样本后，可独立检查它的 30 个三角形。USD 每个形状一个 Mesh，坐标在形状自身空间；JSON 保留部件变换的八个原始分量。OpenUSD 回读的 30 组三个顶点及索引与解码记录逐值一致。整棵树的节点寻址、变换中第四分量、碰撞面朝向与 Chaos 命中还没有通过原作或引擎查询验证。

362 份带刚体且无树的资源中，291 份能越过每体 80 字节记录，完整恢复后续部件形状。木碎块样本有 5 条刚体记录，UE 从碰撞 FBX 得到 3 个箱体。另一类证据来自 6,853 份不同内容的 `*.physics` PhysicsAsset EBX，其中定向驱动约束数组共有 307 条引用，锁定线性和角约束数组均为空。`joint-study.json` 提供源端点、局部锚点和轴、弹簧与阻尼参数样本。端点特殊值如何映射到 Chaos、刚体激活顺序及动力学响应待验。

陶罐的 DebrisClusterData 记录一条有 8 个子节点的根记录，每个叶的 split speed threshold 为 0.5，同一 EBX 中有 8 个质量值为 5 的刚体对象，直接绑定的刚体指针数组为空。用 `StaticScene` 得到层级、部件号、速度和源刚体字段。用 `StaticMesh -SplitParts` 生成处于共同静态姿态的 FBX 节点，按部件和 section 分开，保留材质槽与顶点属性。在 UE 导入时关闭 Combine Meshes，陶罐实际得到 8 个 StaticMesh，逐块面数为 138、198、212、214、182、108、126、210。源文档仍不足以确定破碎时的约束释放过程。

## 重现核查

本机完整目录的 81,435 条 MeshSet 记录中，按解包内容与元数据去重得到 5,097 份刚性、1,233 份骨骼、140 份复合 MeshSet。刚性资源有 17,095 个 LOD，其中 160 个内联。对 68 份真实刚性资源的样本逐 section 读取，覆盖普查发现的全部 83 种顶点声明。这个覆盖率的分母是顶点声明种类。
