# Anthem 音频播放图、语言与混音

## 手动复现

在含有 `Run-Anthem.ps1` 的目录打开 PowerShell。下列命令复用已有的全量解包；可以用 `-Output` 指定另一个含 `catalog.sqlite` 和 `raw` 的目录。

```powershell
$dst = Join-Path $PWD 'output/audio-coverage'
.\Run-Anthem.ps1 -Mode AudioDecodeAudit -Workers 8 -Destination $dst
.\Run-Anthem.ps1 -Mode AudioVoiceAudit -Destination $dst
.\Run-Anthem.ps1 -Mode AudioVoiceDecode -AudioLanguage en -Workers 8 -Destination $dst
.\Run-Anthem.ps1 -Mode AudioStudy -Destination $dst
```

`AudioDecodeAudit` 对本安装所有 NewWave 库逐条解码；指定 `-AssetId` 可只验收一份库，结果写到单独的 ID 子目录。每段 SPS 和每个解码 WAV 只在工作目录中临时存在。要留下某个变体的 WAV，使用原有的 `-Mode Audio -Match <NewWave 完整逻辑名> -Variation 0`。每个 JSONL 文件每行对应一份源资产，行内保留各变体和分段。

`AudioVoiceAudit` 读取对话音库的语言指针、字幕键、变体索引和完整音频块候选。`AudioVoiceDecode` 实际解码指定配音语言并保存 PCM 摘要。`AudioStudy` 生成采样器清单、混音预设清单、代表对话 WAV 和两段受控播放示例。图分析会复用同一解包目录的 EBX GUID 索引；已有索引也可通过 `-GraphIndex '…\texture-graph.sqlite'` 指定。找不到时会从解包文件构建一次，首次运行耗时较长。

只导出一条英文语音，或只查一份音乐图、混音预设，可运行下列命令。旧式 `SoundWaveAsset` 的输入是 EBX。英文音轨和中英文字幕分别保存在音轨和文本表里。

```powershell
$conv = 'conversations/dungeons/dungeon_07/dun_07_gatekeeperarrival'
.\Run-Anthem.ps1 -Mode AudioTrace -Match "$conv.vo.en" -Variation 8 -Destination $dst
.\Run-Anthem.ps1 -Mode AudioTrace -Match $conv -Destination $dst
.\Run-Anthem.ps1 -Mode AudioTrace -Match 'sound/music/01_core/system/mus_ui_music_asset' -Destination $dst
.\Run-Anthem.ps1 -Mode AudioTrace -Match 'sound/system/mixers/signalactivated/signalactivated_music_duck_diegetic' -Destination $dst
```

`AudioTrace` 支持按精确名或 EBX 目录 ID 选择。音库可用 `-All` 保留每条 WAV。图报告保留 Data 与 Patch 各份来源、文件及对象 GUID。对话报告中 `spoken_banks[].tracks[].subtitles` 提供字符串 ID，`text_tables[].text` 用同一 ID 索引语言文本；可用 `chunk_unresolved` 筛出缺少可用完整块的变体。

## NewWave 解码验收

4,411 份不同内容的库，24,265 个变体和 25,257 次分段引用全部完成一次 16 位 PCM 解码，错误数为 0。共核对 6,395,617,933 采样帧、29,569,548,202 字节 PCM，含 187 个多段变体。验收项为源库和完整块 SHA-256、SPS 块链、解码声道、采样率、音频帧数、实际 PCM 字节数、各段连续起点及段序。该过程产生 15 种实际编码／声道／采样率组合。逐变体的 SHA-256 对应依次拼接的 PCM，不含 WAV 头。全量结果在 `decode-audit.json`、`decoded-variations.jsonl`。18 个既有 UE 5.8.4 样本共 31 段，与本轮 PCM 哈希逐条吻合，交叉核对见 `sample-crosscheck.json`。完整 UE 保存重开验收的数量仍为 18。 [vgmstream r2168](https://github.com/vgmstream/vgmstream/releases/tag/r2168)

## 循环范围与播放开关

143 个变体在库中有明确循环范围。其余 24,122 个写为 `0,0`，且无 SPS 循环起点。工具从 SoundPatchConfigurationAsset 的配置对象追回主图采样器，读取 `SamplerNodeData.Looping`、触发和释放端口。配置 Wave 须关联到外部 NewWaveAsset；按同名及有序 chunk GUID、大小匹配实际库。跨版本主节点必须给出一致的开关。普查把不同节点对同一库内容／变体分别写入 `sampler-bindings.jsonl`，汇总见 `sampler-coverage.json`。

在 `sound/sfx/soundpatches/*` 的 4,569 份 EBX 中，4,372 份是声音配置。工具沿 16,514 个外部配置引用和本地对象解析到 5,837 个具备波形及开关证据的配置项。按库内容和变体号去重，可关联 13,387 / 24,122 个默认变体。其中 881 个只见开启，12,444 个只见关闭，62 个同时见到两种用法。其余 10,735 个在这次扫描范围内没有对应结论。例如 `bw_underwater_synth_rumble` 的变体 0 在 `env_plc_golem_area_emitter_lp` 中开启循环，在 `env_bw_underwater_shaper_rumble` 中关闭。工具保留每条调用路径；StepLogic 的 4,034 个配置使用另一类节点，未参与 Looping 布尔值统计。

Ranger 激光样本中，三条双段持续音的库索引都是 `0,0`，主图节点开启循环；21 条起音／停止等单段变体的主图节点关闭循环。逐节点可查 `patch.json` 里的 `configured_wave`、`profiles[].looping`、`trigger` 和 `release`。主图上的布尔值说明被触发时采样器的配置；停服后无法观测玩家何时触发、释放、切换或覆盖它。多段的实际回跳边界仍缺独立证据。导出器保持单遍 PCM，只给有明确范围的 WAV 写 `smpl`。

## 交互音乐

主菜单的 Data 和 Patch 两份 MusicAsset 均解析出五个具名选择事件。报告记录事件的外部 GUID、选择器、目标、默认或指定过渡、淡化方式、乐句的候选片段及其 SoundWaveAsset。音乐资产默认 90 BPM，主菜单前奏和后继片段各自为 96 BPM、4 拍。

| 事件 | 默认目标 | 作者设置 |
| --- | --- | --- |
| Start | Main_Menu_Intro | 立即同步，默认淡入和淡出为 0 |
| StopReal | Silence | 立即同步，等功率淡出 11 秒 |
| Screen_EoE | Screen_EoE_Normal | Interrupt，立即同步 |
| Credits | Credits | Fade，默认淡出 7 秒 |
| Start_Bwaaaaah | 空目标 | 默认过渡含 OverlayControl |

`Start-StopReal.wav` 保留补丁前奏源容器的 48 kHz、8 声道。测试在第 3 秒注入 StopReal，按源片段 −6 dB 和预设淡出时长生成 14 秒 WAV，回读验证末帧静音。使用余弦实现等功率淡出。前奏另有进入主菜单循环片段的 NextPlayable 指针、4 小节淡出和 2 拍淡入，本试听只覆盖 StopReal 分支。八声道的最终声像、各层实时音量、玩家事件序列和原作引擎的精确插值仍待对照。

## 对话、配音语言与字幕

`conversations/*.vo.*` 含 5,058 个逻辑名、5,140 份不同 EBX 内容，共 215,295 个变体。每条变体都读取了 SoundWaveAsset 的 Localization 范围、目标 AudioLanguage 及字幕键。英文有 42,754 条唯一完整块候选，德语 42,456、西语 44,105、法语 42,932、意语 43,048 条均有语言／字幕索引，这四种语言在本安装目录中缺少匹配的完整块。统计按内容版本保留 Data／Patch，不代表不同剧本台词数。查询明细见 `spoken-variations.jsonl`、`voice-coverage.json`；实际解码见 `decoded-voices-en.jsonl`、`voice-decode-en.json`。

英文 1,031 份音库的 42,754 个变体均已解码，覆盖 42,755 段、5,158,300,024 个采样帧，错误数为 0。这套解码走旧式 SoundWaveAsset，独立于前面的 NewWave 普查。报告保留段偏移、段和拼接 PCM 摘要。

五种配音索引合计引用 33,256 个不同数字文本 ID。补丁英文表命中 33,256 个，补丁中文表命中 33,249 个；基础英文、中文表各命中 30,134、30,127 个。补丁中文缺少的七个 ID 为 141552、141557、141570、141571、141578、141579、141587。文本读取器按本安装表头中的辅助记录数定位 UTF-8 字典，校验记录数、长度和文件尾，并保留每份表的 SHA-256。 [Frosty 本地化读取代码](https://github.com/CadeEvs/FrostyToolsuite/blob/1.0.6.3/Plugins/BiowareLocalizationPlugin/LocalizedResources/LocalizedStringResource.cs)

第七地下城守门人对话的 Data／Patch 各有同一批 18 个 ConversationLine。五种配音索引各关联其中 15 个文本 ID。英文 20 个变体全部已导出 WAV，个别台词有多个录音。例 `177990_0_0` 对应英文变体 8，文本 ID 177990 对应 “His funeral.” 和“那算他倒霉。”另外三个对话 ID 在英文表存在，本样本未找到对应录音和中文文本。键末尾的两个数字按原文保留；逐条播放时的分支选择、玩家角色与音色切换仍需游戏状态。

## 空间路由与混音

Ranger 激光配置的四个输出为玩家直出 LFE、玩家直出 Noise、玩家 Flat 及非玩家 Object。主图中前三项经 Wep_Player → _Gameplay_Player，第四项经 Wep_Npc → _Gameplay_Npc，再汇入 Gameplay → SFX_Normal → SFX → Master。报告分别记录主图默认和配置覆盖值、属性掩码、主发送、辅助发送、变换源相关端口和位置输入。

`sound/system/mixers/*` 下有 128 个逻辑名，138 份 MixerAsset 均已读取。138 个预设共 558 条组配置，558 条均可解析到目标组；另有 1,338 个属性值及 149 条动态设值记录。`mixers.json` 保留 Gain、Pitch、LFE、Reverb、LPF 的实际字段、Attack、Release、加法和优先级，以及两份 MixerSystem 的父总线链。

场景音乐压低预设作用于 Mus_Diegetic → Music → Master，Gain、LFE、Reverb 各为 −12，LPF 为 400，Attack 为 1 秒、Release 为 3 秒。`Mus_Diegetic-gain.wav` 取实际酒吧音乐第 4 号变体，测试在第 1 秒启用、第 4 秒释放，单独施加 Gain，并在 dB 域线性过渡。WAV 与源 PCM 的实测电平差在启用前、保持段和释放后分别为 0、−12.00001、0 dB。该试听没有施加 LPF、LFE、混响或其他同时活动的预设。预设仲裁、逐帧检测电平、听者姿态、遮挡、最终扬声器输出和关卡混音仍需原作运行数据。 [Frosty Anthem SDK](https://github.com/CadeEvs/FrostyToolsuite/blob/1.0.6.3/FrostySdk/Profiles/AnthemSDK.dll)
