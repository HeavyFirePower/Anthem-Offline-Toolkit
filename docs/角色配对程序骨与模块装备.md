# Anthem 角色骨架、程序骨与模块化装备

本轮从已解包的 Patch 选取 9 个角色或外骨骼基础网格、5 件 Interceptor 装备，分别导出 LOD0 蒙皮 FBX。验证工程使用 UE 5.8.4。之前的 Spacebear 六级 LOD 和三段动画另有独立记录。[Spacebear 骨架与 FBX](骨骼模型与UE导入.md)

## 重现与查看

在游戏目录（含 `Run-Anthem.ps1`）打开 PowerShell。第一条命令生成 FBX、权重、程序骨映射和一段真实动画。第二条命令使用刚生成的文件，在 UE 中导入、保存，再从新的编辑器进程重新打开。工具也支持用 `-Mode SkeletalStudy -ImportUE` 连续执行两步。

```powershell
$study = .\Run-Anthem.ps1 -Mode SkeletalStudy -Lod 0
.\tools\Validate-SkeletalStudyUE.ps1 -Manifest $study
```

默认读取相邻的 `../Anthem-Extracted/anthem`，产物在解包目录的 `converted/skeletal-study`。可用 `-Output` 和 `-Destination` 更改输入、输出路径，用 `-EngineRoot` 指定 UE 安装目录。保留 Autodesk FBX SDK 的安装要求。只验证指定的一对网格和骨架，可使用原有的 `-Mode SkeletalMesh -AssetId … -SkeletonId …`，需要核查源引用时加入 `-OwnerId`、`-MasterId`。

在随工具提供的 `ue/AnthemValidation/AnthemValidation.uproject` 打开内容浏览器，进入 `/Game/AnthemValidation/SkeletalStudy/LOD0`。

- 打开 `L_InterceptorEquipment`，选中 Interceptor，展开组件即可查看基础内衬和四件默认外装。
- 在网格组件对应的 Skeletal Mesh 资源上查看 Skeleton、权重、分区与材质槽。在 `SK_hmm_passive01_model_mesh_lod0` 的骨架树显示 Mesh Sockets，可按 `VJ.` 搜索人体锚点。
- 打开 `A_EXM_EXP_Underwater_Glide_Stop_Up_8001a79ef7e144d4`，更换预览网格为 Ranger、友方 Freelancer 或 Corvus Sentinel，可查看同一动作在不同几何上的效果。各自的顶点数不同。
- 打开 `A_Colossus_EXM_Underwater_Arms`，可在 Colossus 自己的骨架上查看从这段 Ranger 动作迁移的双肩至双手动作。
- `A_interceptor_IKStudy`、`A_ranger_IKStudy` 和 `A_human_IKStudy` 是用原作链映射制作的受控动作。目标与极向量写入 build 报告。为验证未受手臂影响的部件，峰值帧另含 12 cm 根位移。

| Interceptor / Colossus 内衬 | 202 / 183 | 29,664 / 26,076 |
| Storm / Ranger 内衬 | 223 / 183 | 26,343 / 29,545 |

9 个基础样本的证据依次为角色模板导入表中的网格与主骨架对象、SkinnedMeshAsset 中的 MeshSet RID、MasterSkeleton 的 Skeleton 指针。模板导入表记录文件与对象的 GUID 对。5 件装备另从外观条目找到装备槽和对象蓝图，在蓝图里解引用 MeshProxyEntityData，核查 SkinnedMeshAsset 和 RID，再在 Interceptor 骨架上检验绑定与运动。默认腿甲省略了 MeshSet 顶层骨数，此样本的 LOD0 骨索引完整且按顺序覆盖 0 至 201。

14 个文件均经 Autodesk SDK 重新打开。UE 逐项回读骨名、父节点、模型空间参考姿势与 MeshDescription 中的源点权重。265,757 个控制点的骨名和量化回的权重字节全部匹配。最大单项权重误差为 2.97×10⁻⁸，关节位置最大单分量误差为 0.0000542 cm。此处的计数覆盖本表 14 个 LOD0。此前 1,233 份 MeshSet 的普查覆盖骨表和声明，尚无全量配对成功率。

另有一个可复查的未决样本。男性平民模板引用的网格声明 162 骨，主骨架指向 313 骨 HMM，SubSkeletons 为空。另一个 162 骨 HMMNF 的所有名字均能在 HMM 中找到，同名骨的父名也一致，但只有 52 个同序位置的名字匹配，绑定矩阵也有差异。模板和主骨架均无指向 HMMNF 的导入。工具将该对写入 `unresolved_human`，待查实际重映射。

## 程序骨与装备

从共享 ANT AssetBank 跟踪 RigAsset、FeatureCollection、JointMappingFeature、模板 ID、各 rig 的有符号关节索引，最后匹配 ANT 关节名称、直接父级和 EBX 骨架。6 套 rig 的 IK 链列表共 64 项。Interceptor、Colossus、Ranger、Storm、HMM、HMF 分别有 8、8、8、10、16、14 项。各项的根、中段和末端均有对应骨及一致的直接父级。程序骨报告同时保留 IKMode、目标及可选第二中段的解析结果。部分条目共享链定义，64 是按 rig 计数。

对 EXF 和 EXM 的左臂，用 UE 双骨 IK 求解器驱动 LeftArm、LeftForeArm 和 LeftHand。受控目标、极向量和关节位置可在报告中核对。装备用 UE 原生 Leader Pose 跟随内衬。五个时刻、每件装备均匀取 128 个 LOD0 渲染顶点，用 UE 的 CPU 蒙皮求值，与同一件装备独立播放同一姿势逐点比较。重开关卡后，工具在原胸甲组件上完成默认 → Bomber → 默认的替换，复核变形，并测试拒绝骨架不兼容的 Colossus 网格。[Epic 模块化角色说明](https://dev.epicgames.com/documentation/unreal-engine/working-with-modular-characters-in-unreal-engine)

共享库中 29 个 RelativeIkVirtualJoint 在 HMM 和 HMF 各找到 29 个父骨，对应 Vector3 默认偏移均为零。工具在 HMM 样本网格创建 29 个 UE Mesh Socket，用作默认相对位置的锚点。重新打开资产后，对三个姿势逐一核对父骨和锚点位置。HMF 的覆盖到源数据解析；其网格尚未经过本轮锚点回放。游戏运行时如何覆盖这些参数、驱动求值顺序、完整 ANT 约束栈，以及带程序骨高位标志的蒙皮权重仍待验证。

## 跨角色复用

Ranger、友方 Freelancer 和 Corvus Sentinel 引用同一份 EXM SkeletonAsset，完整有序绑定数据一致。UE 中三个 SkeletalMesh 也共享同一个 Skeleton 资产。原作水下动作从 ECLP 解出 64 条骨轨，30 fps，2 秒，含首尾共 61 个姿势。回读 UE 压缩动画时，六个检查帧相对导出轨道的最大局部位移误差为 0.00376 cm，最大角误差为 0.0251°。重开编辑器后，三个网格六帧的五处身体关节位置差均为 0 cm，各网格抽样顶点的最大位移分别为 21.00、88.69 和 96.91 cm。

Ranger 和 Colossus 同为 183 骨，按 Ranger 的名称在 Colossus 中查找，缺少 51 个名字，另有 5 个同名骨父级不同。以 Interceptor 为起点核查 Storm，分别为 74 和 6。完整有序绑定不同的模型需要单独的骨架和映射。[Epic Skeleton 资产说明](https://dev.epicgames.com/documentation/unreal-engine/skeletons-in-unreal-engine)

对 Ranger → Colossus 成功迁移了双臂 8 条旋转轨。左右各检查 Shoulder、Arm、ForeArm 和 Hand 的父子关系，以静止的 Spine2 为起点，计算源骨相对于绑定姿势的组件空间旋转变化，再用目标骨绑定方向和父骨旋转重建本地旋转。目标模型保留自身的骨长、局部位移及缩放。保存后重新载入 Colossus 的 AnimSequence，六个检查帧的最大旋转变化误差为 0.00349°，128 个均匀抽样渲染顶点中观察到最大位移 2.37 cm。本样本保留双臂动作，躯干、根运动、腿及足部接触尚未迁移。
