# Anthem 格式修复与验证说明

本文的 OBJ 记录属于最初的预览样本。刚性模型、碰撞和静态模型组的后续实测见[静态模型与场景](静态模型与场景.md)。

## 上游和修改

AnthemTool 源码固定在 `a2fec1ac0b596765c9d1f620d9167353a1b39582`。保留 `vendor/anthemtool/LICENSE.md`。本项目修改以下行为：

1. `sb/bundle.py`：使用 bundle 的 data offset 和 location offset 读取逐资源 CAS-change 标志。移除原来根据地址外观猜测 CAS ID 的主流程，本安装补丁中该猜测会错位。
2. `toc/index.py`：即使 bundle 数量为零仍解析 TOC 资源。此安装的六个语言 TOC 共含 2524 条这类记录；原实现会提前返回并漏掉它们。
3. 同文件按 24 位顺序字段处理资源顺序，避免将标志和顺序混淆。
4. `tools/anthem_pipeline.py`：显式 x64 Oodle ABI、CAS 范围/块边界检查、解压长度检查、原子替换、输出 SHA-256、重试和断点校验、来源数据库。SHA-256 是解压结果校验；`source_sha1` 是包中的原始字段，没有假定二者采用相同哈希语义。

输入指纹包含路径、文件大小、mtime 和 TOC/SB 内容哈希，不是 86 GB 安装的全文件内容哈希。CAS 数据内容若被外部修改但时间/大小同时伪装不变，指纹不能发现；原始安装应保持稳定。

## 小样本范围

样本刻意保留较少资源；按种类选择较小资源，再补充有辨识度的纹理、一个 skinned MeshSet 及其依赖。多个 chunk 记录可能具有相同内容，因为来源、逻辑范围或元数据不同。记录数不能当作独立美术资产数量。

最终范围以 `output/sample/summary.json` 为准。`sample_selection.json` 记录最初选择及其来源，依赖解析后会新增记录。初始样本使用局部索引。后续手动完成的全量索引与解包位于 `Games/Anthem-Extracted/anthem`。

## 已执行的检查

- 实际游戏 Data/Patch 的元数据解析，通过修复后的显式地址表读取。
- 每个样本解压时检查 CAS 范围、块长度和可用的原始尺寸；保存 SHA-256。
- 完整纹理 mip 尺寸与块压缩尺寸相符，匹配完整 chunk；DirectXTex 实际读取并解码五个 DDS。
- 两个 rigid 网格的顶点声明、法线长度、索引范围和 AABB 检查；分别为 258 顶点/256 三角形和 24 顶点/12 三角形。
- 64 个 DXBC 容器结构检查及微软反汇编成功。
- UE 5.8.4 实际导入五张 TGA 和两个 OBJ，检查资源类型和网格顶点/三角形数量；见 `ue_import_report.json`。
- 四项自动测试：无 bundle 的 TOC 仍保留 chunk、截断 CAS 拒绝且保留旧输出、DXBC 边界/误匹配检查、样本 DDS 头与 mip 数据一致性。

## 文件说明

工具包不包含游戏原文件、Oodle DLL、已提取的游戏资源或 UE 缓存。使用现有目录时这些内容仍保留在原位置。外部来源和实际 SHA-256 列在 `docs/tool_sources.json`。

完整提取仅在你手动运行 Index/Extract 后发生。验证用的 UE 工程与原始文件保持分离；重跑 UE 验证只替换专用测试目录下同名资产。
